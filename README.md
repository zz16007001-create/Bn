# نُخبة البن للتوزيع — نظام إدارة شركة توزيع البن والمنتجات الغذائية (PWA)

تطبيق ويب تقدمي (**PWA**) باللغة العربية الكاملة (**RTL**) مصمم للعمل على هواتف **Android** والحواسيب **بدون إنترنت بالكامل (Offline-First)** عبر قاعدة بيانات محلية `IndexedDB (Dexie)` مع حفظ المبالغ بالقروش (`Integer Piastres`) لتفادي أخطاء الكسور العشرية.

---

## المميزات المكتملة (المراحل 1 إلى 5)

1. **العمليات اليومية الكاملة**:
   - شاشة **فاتورة البيع السريعة** (كل الأصناف مرئية تحت بعضها + خانة كمية مباشرة + تبديل قطعة/كرتونة + إجمالي لحظي + حفظ في 3 نقرات).
   - **المبيعات والمرتجعات**، **فواتير المشتريات ومرتجعات المشتريات** مع إعادة حساب متوسط التكلفة المرجح تلقائياً.
   - **إدارة الأصناف والمخازن** (متعدد المخازن، تحويل بين المخازن، جرد فعلي، استيراد أصناف من Excel، سجل حركات مخزون لا يُحذف).
   - **العملاء والموردون** وكشف الحساب والتحصيلات والمدفوعات.
   - **الخزنة والمصروفات**: الخزنة تسجل المدفوع فعلياً فقط، مع إقفال يومي ومصروفات بتصنيفات قابلة للتوسيع، ولا تُنشأ أي حركة دون مستند مصدر ومعرّف فريد لمنع التكرار.
   - **لوحة التحكم والتقارير**: الأرباح والمبيعات والتحصيلات والديون والمصروفات وتصدير التقارير.

2. **الطباعة الحرارية والبدائل (المرحلة 5)**:
   - رسم الفاتورة كصورة **Canvas** بخط **Cairo** المحلي واتجاه **RTL** (لتفادي مشكلة تقطيع الحروف العربية في الطابعات الحرارية).
   - دعم ورق **58mm** و **80mm** عبر الإعدادات، مع طباعة تلقائية بعد الحفظ (قابلة للإيقاف) وإعادة طباعة الفواتير السابقة.
   - الإرسال عبر **Web Bluetooth (BLE)** بصيغة **ESC/POS Raster (`GS v 0`)** مقسّماً إلى حزم صغيرة (`Chunks`) مناسبة لـ BLE، مع حفظ آخر طابعة وإعادة الاتصال وزر اختبار الطباعة.
   - **بديل احتياطي موثوق دائماً**: معاينة الفاتورة وحفظها/طباعتها كـ **PDF** أو مشاركتها كصورة **PNG** (مثلاً عبر واتساب).

3. **الأمان والصلاحيات وسجل المراجعة والنسخ الاحتياطي**:
   - تسجيل دخول برمز **PIN** مشفّر (`SHA-256 + Salt`) مع 4 أدوار وظيفية و13 صلاحية مفروضة على الواجهات ومستودعات البيانات.
   - **سجل مراجعة (Audit Log)** غير قابل للتعديل يسجل القيم **قبل التعديل وبعده** مع بحث وفلترة متقدمة.
   - **نسخ احتياطي محسّن**: ضغط `Gzip (.json.gz)` + خيار `JSON` + بصمة تحقق سلامة `SHA-256` تفحص الملف قبل لمس قاعدة البيانات + ترقية تلقائية عند استعادة نسخة أقدم + تذكير يومي + زر تفعيل حماية التخزين الدائم (`Persistent Storage`).

## تحذير تقني صريح ومهم حول طابعات البلوتوث الحرارية (BLE مقابل Bluetooth Classic)

> **ملاحظة صادقة للمستخدم قبل شراء أو استخدام طابعة:**
> - متصفح الويب (حتى **Google Chrome على Android**) يدعم فقط بروتوكول **Bluetooth Low Energy (BLE / GATT)** عبر واجهة `Web Bluetooth` ولا يدعم بروتوكول **Bluetooth Classic SPP (Serial Port Profile)**.
> - بعض الطابعات الحرارية الرخيصة أو القديمة تعمل بـ **Bluetooth Classic SPP فقط**؛ هذه الطابعات قد تظهر في إعدادات بلوتوث الهاتف لكنها **لن تظهر أو لن تقبل الاتصال من داخل المتصفح**.
> - كذلك **لم يتم اختبار هذا التطبيق فعلياً مع جهاز طابعة بلوتوث حرارية مادي** داخل بيئة التطوير البرمجية؛ الكود مبني وفق المواصفات القياسية لبروتوكول ESC/POS Raster عبر BLE.

### كيف تتحقق من توافق طابعتك في 3 خطوات؟
1. افتح التطبيق على هاتف Android باستخدام **Google Chrome** عبر رابط **HTTPS** (رابط Vercel مثلاً).
2. اذهب إلى **الإعدادات ← الطابعة الحرارية** واضغط **«بحث والاتصال بطابعة BLE»** مع تشغيل الطابعة.
3. إذا ظهرت الطابعة وتم الاتصال، اضغط **«اختبار الطباعة»**:
   - إذا طُبع الإيصال العربي بوضوح: طابعتك متوافقة مع BLE وتعمل مباشرة.
   - إذا لم تظهر الطابعة أو فشل الاتصال بـ GATT: فطابعتك تعمل بـ Bluetooth Classic فقط؛ وفي هذه الحالة استخدم زر **«طباعة / حفظ PDF»** أو **«مشاركة صورة (واتساب)»** لإرسال الفاتورة لتطبيق الطابعة الرسمي على الهاتف أو مشاركتها للعميل فوراً.

## دليل المبتدئين الكامل: من تنزيل الملفات حتى النشر على GitHub وVercel والهاتف

### الخطوة 1: تنزيل ملفات المشروع على جهازك
1. قم بتنزيل ملف المشروع المضغوط (`ZIP`) وفك الضغط عنه في مجلد واضح على جهازك (مثلاً: `nukhbat-albonn`).
2. تأكد من وجود ملفات `package.json` و `package-lock.json` و `vercel.json` و `index.html` ومجلد `src` مباشرة داخل هذا المجلد.
3. **ملاحظة مهمّة عند الرفع اليدوي**: لا ترفع مجلد `node_modules` أو `dist` أو `.aistudio` أو ملف `metadata.json` إلى GitHub (ملف `.gitignore` يستثنيها تلقائياً عند استخدام Git).

---

### الخطوة 2: إنشاء حساب GitHub ورفع المشروع

#### الطريقة الأسهل (عبر GitHub Desktop أو سطر الأوامر Git — تحترم `.gitignore` تلقائياً):
1. أنشئ حساباً مجانياً على [github.com](https://github.com) واضغط **New repository** (مثلاً باسم `nukhbat-albonn-pwa`، واختر **Private** ليبقى الكود خاصاً).
2. نفّذ الأوامر التالية داخل مجلد المشروع (يُفضّل Node.js 22 المحدد في `.nvmrc`):
   ```bash
   git init
   git add .
   git commit -m "الإصدار الكامل 1.0.0 - نُخبة البن للتوزيع"
   git branch -M main
   git remote add origin https://github.com/اسم-حسابك/nukhbat-albonn-pwa.git
   git push -u origin main
   ```
3. عند الرفع على GitHub، سيعمل فحص **GitHub Actions CI** (`.github/workflows/ci.yml`) تلقائياً باستخدام `npm ci` لتشغيل `npm run lint` ثم `npm test` ثم `npm run build` للتأكد من سلامة الكود مع كل تحديث.

---

### الخطوة 3: النشر المجاني على Vercel (استضافة ثابتة Static SPA)
1. افتح [vercel.com](https://vercel.com) واضغط **Sign Up** واختر **Continue with GitHub**.
2. من لوحة Vercel اضغط **Add New...** ثم **Project**.
3. اختر مستودع `nukhbat-albonn-pwa` واضغط **Import**.
4. سيتعرف Vercel تلقائياً من ملف `vercel.json` على جميع الإعدادات الصحيحة:
   - **Framework Preset**: `Vite`
   - **Install Command**: `npm ci`
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
5. **لا تحتاج لإضافة أي متغيرات بيئة (Environment Variables)** لأن النظام يعمل محلياً بالكامل بدون خادم أو مفاتيح API.
6. اضغط **Deploy** وخلال دقيقة ستحصل على رابط **HTTPS** دائم لتطبيقك.

---

### الخطوة 4: تثبيت التطبيق على هاتف Android للعمل بدون إنترنت
1. افتح رابط Vercel في متصفح **Google Chrome** على هاتف Android.
2. أنشئ حساب المدير الأول وحدد رمز **PIN**.
3. اضغط زر **«تثبيت التطبيق»** الظاهر في الشريط العلوي (أو من قائمة Chrome `⋮` اختر **تثبيت التطبيق / Install app**).
4. بعد التثبيت، افتح التطبيق من أيقونته على الشاشة الرئيسية، ثم اذهب إلى **النسخ الاحتياطي ← «تفعيل حماية التخزين الدائم»** لحماية بيانات `IndexedDB` من التنظيف التلقائي لنظام Android.

---

### الخطوة 5: تحديث التطبيق مستقبلاً دون فقدان أي بيانات
1. **نصيحة ذهبية قبل أي تحديث**: افتح التطبيق ← **النسخ الاحتياطي** ← نزّل نسخة مضغوطة (`.json.gz`) واحفظها على هاتفك أو Google Drive.
2. ارفع التعديلات على نفس مستودع **GitHub** (وسيبدأ **Vercel** النشر التلقائي خلال دقيقة).
3. عند فتح التطبيق على الهاتف مع وجود إنترنت، سيقوم الـ **Service Worker** بتحميل التحديث في الخلفية تلقائياً (`autoUpdate`)، وستبقى جميع فواتيرك وأصنافك وحساباتك محفوظة داخل `IndexedDB` مع ترقية هيكل الجداول تلقائياً (`Migrations`) دون مساس بأي سجل.

## أوامر التطوير والاختبار (باستخدام npm فقط)

```bash
npm ci           # تثبيت الحزم بدقة من package-lock.json
npm run dev      # تشغيل خادم التطوير على المنفذ 3000
npm run lint     # فحص TypeScript (tsc --noEmit)
npm test         # تشغيل جميع اختبارات Vitest الآلية
npm run build    # بناء نسخة الإنتاج في مجلد dist
npm run preview  # معاينة نسخة الإنتاج محلياً مع الـ Service Worker
npm run clean    # حذف مجلدات البناء المؤقتة (dist و dev-dist)
```
